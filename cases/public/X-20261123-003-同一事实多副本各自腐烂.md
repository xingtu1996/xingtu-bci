# X-20261123-003 · 同一事实多副本，各自腐烂

- 状态：`verified`（维护者自己的坏例索引，已脱敏改写）
- 核对日期：2026-11-23

## 现象（一句话）

一个枚举值变更后，多处说明文档**同时过期**；清单类事实的手写索引只命中一小部分；最讽刺的是——坏例索引自己也是受害者：索引表落后于详情小节若干条，编号还出现跳号。

## 根因

- **机制性根因**：复述成本为零、同步成本被遗忘。每一处副本都被后来的协作者当成与新决策**同样权威**。
- 编号类事实没有「取号即落池」的强制路径，手写号必撞。
- **文档越旧，语气越确定**——模型不会怀疑读到的文档已经过期，这是最隐蔽的失效模式。

## 预防（可执行）

1. 枚举类事实**禁止内联复述**，改写为「取值以 X 文件 / 字段为准」的指针。
2. 易漂移清单收进**机器可读注册表**，单一事实源，其他处只引用。
3. 一条 lint 扫全部声明面，漂移即非零退出，进常规门禁。
4. 编号一律走程序取号（自动顺序 + 去重），禁止手写。
5. 登记条目必须**同时**写索引表行与详情小节，做对称性校验（表行数 vs 详情数、集合差集）。

## 执行教训（通用化）

> **「多写一份方便查」是复利，也是负债。** 判断标准：这份副本会不会漂移？会 → 它就该是指针，不是副本。读旧文档时要主动问一句「它最后一次更新是什么时候」。
