# X-20261123-002 · 成功回执不等于结果落地（并发写覆盖）

- 状态：`verified`（维护者自己的坏例索引，已脱敏改写）
- 核对日期：2026-11-23

## 现象（一句话）

按「收尾即留痕」追加一条记录，工具回显「已插入」，紧接着复核发现**该条根本不在文件里**；同一时间窗有多个写入者在写同一批共享文件。

## 根因

- **机制性根因**：追加工具是裸的「读全文 → 内存插入 → 整体回写」，**无锁**。两个写入者各读旧快照，后写者覆盖先写者的行（lost update）。
- **写完不复核**：把「内存里算出的新内容」当成「已落盘」；「已插入」只证明字符串拼好了，**不是落盘凭证**。

同类变体：同一文件在同一条消息里并发发起多处编辑，只落部分，留下自相矛盾的状态——各编辑基于读时快照整文件写回，后提交覆盖前者。

## 预防（可执行）

1. 跨工具共享的登记表（变更日志 / 台账 / 索引 / 清单），新写前先问「**有没有第二支笔**」，有就上并发控制。
2. 落盘四件套：**独占锁 + 锁内每轮重读 + 原子替换 + 写后复核**。
3. 复核命中才是凭证；「已插入 / Successfully edited」降级为**假设**，不在文件里就重试，仍失败非零退出。
4. 同一文件多处改动：串行，或**单次整块替换**；禁止基于旧快照的并发整文件写回。

## 执行教训（通用化）

> **凡是「成功」的回执，都要一次独立读回作为凭证。** 尤其是共享文件——成功提示证明的是「我想做了」，不是「做成了」。
