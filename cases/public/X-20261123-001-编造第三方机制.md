# X-20261123-001 · 批量生成时用「合理推测」补齐不熟的第三方机制

- 核对日期：2026-11-23

## 现象（一句话）

批量产出内容时，把某个开源项目的核心机制写成了一组**听上去通顺、官方文档里根本不存在**的说法；关键数字取自二手转述，和官方基准对不上。

## 根因

- **机制性根因**：门禁只查形式（格式 / 腔调 / 脱敏），不查**事实**。模型对不熟悉的具体项目会用「合理推测」补全，而通顺的命名让编造难以被肉眼发现。
- 二手转述被当成一手依据；数字脱离原始基准后失真。

## 预防（可执行）

1. 涉及具体第三方项目的机制与数字，**必须回一手源**（官方 README / 文档 / 仓库）核对后才落笔。
2. 二手转述不得作为依据；找不到官方说明就**不写机制**，宁可留空。
3. 批量流水线的验收标准必须包含**事实项**，不能只有形式门禁。
4. 已成稿走事实核查流程，按证据强度分档标记。

## 执行教训（通用化）

> 一个人名/项目名越具体、叙述越通顺，越要警惕它是被补全出来的。**「读起来对」不是证据，「一手源里有」才是。**
