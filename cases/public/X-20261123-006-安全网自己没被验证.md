# X-20261123-006 · 备份"创建成功"是打印出来的，不是落盘的事实

- 状态：`verified`（自有坏例索引，已脱敏改写）
- 核对日期：2026-11-23

## 现象（一句话）

操作前的备份脚本返回非零、备份目录里零文件，但终端照样打印"创建备份: xxx.tar.gz"——**看上去成功了**。事后按纪律核对备份清单，才发现"刚做的那份不在列表里"。

## 根因

- 备份文件名由描述拼接，**描述里的路径分隔符原样进文件名** → 路径被切成不存在的子目录 → 打包命令失败。
- 失败原因被 `2>/dev/null` 吞掉。
- 脚本虽非零退出，但"创建备份"那行**打印在真正打包之前**——成功叙事先入为主。
- 全程没有"备份文件必须存在且非空"的自证。

## 预防（可执行）

1. 描述进文件名前先消毒（路径分隔符 / 特殊字符 / 连续空格 → `-`）。
2. 打包失败显式报错 + 非零退出，禁用吞错重定向。
3. **自证式收尾**：断言文件存在且非空；成功时打印完整路径 + 大小 + 条目数——把"成功"变成可核对的事实。
4. 成功提示必须打印在**实际行动之后**；提前打印 = 伪造凭证。
5. 拿备份当回滚点前，先看目录清单里有没有它——**看落盘结果，不看调用输出**。

## 执行教训（通用化）

> **验证动作本身也必须被验证。** 安全网、门禁、备份这类"保险措施"最容易失效于无声——它们平时不被触发，坏了没人知道。凡是打印"成功"的地方，都要有一次独立的存在性检查；"绿"和"成功"必须是算出来/看得见的，不是宣告出来的。
